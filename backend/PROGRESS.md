# Backend Progress

Tracking current work status for the backend.

**Baseline:** HEAD commit `da37c77` ("format")

---

## Completed

### Core Infrastructure

- Express 5 app (`src/app.ts`) and HTTP server (`src/server.ts`), routes mounted at `/api/v1`.
- Middleware: `authenticate` / `authenticateOptional` (`src/middlewares/authenticate.ts`), Zod `validate` (`src/middlewares/validate.ts`), global error handler (`src/middlewares/errorMiddleware.ts`).
- Environment validation with Zod and fail-fast startup (`src/config/env.ts`); shared constants (`src/config/constants/`).
- Standard success envelope via `ApiResponse` (`src/lib/apiResponse.ts`) and typed errors via `ApiError` (`src/lib/apiError.ts`).
- `asyncHandler` (`src/lib/asyncHandler.ts`), pino logger (`src/lib/logger.ts`).

### Authentication

- Dual JWT strategy: short-lived access token + refresh token with rotation (`src/infrastructure/auth/jwt.ts`).
- Bcrypt password hashing (`src/infrastructure/auth/bcrypt.ts`); HttpOnly refresh cookie scoped to the refresh path (`src/infrastructure/auth/cookies.ts`).
- Session management with revocable, hashed refresh tokens (`sessions` table).
- Endpoints: `register`, `login`, `refresh`, `logout`, `logout-all`, `me` (`src/modules/auth/`).

### Projects Module

- Full CRUD + pagination (`src/modules/project/`).
- Authorization in the service layer: writes owner-scoped, reads honor visibility (PRIVATE hidden via 404).

### Architectures Module

- Full CRUD incl. JSONB graph storage and partial node/edge merge on update (`src/modules/architecture/`).
- Ownership inherited from the parent project; unique `(project_id, name)`.

### Database

- PostgreSQL via Drizzle ORM, single shared connection (`src/infrastructure/database/db.ts`).
- Schemas: `users`, `sessions`, `projects`, `architectures`, `simulations` (+ `simulation_events`, `metrics`), `scenarios` (`src/infrastructure/database/schema/`).
- Typed JSONB shapes: `ArchitectureGraph`, `SimulationConfig`, `ScenarioEvent` union (`src/infrastructure/database/schema/types/types.ts`).
- Migrations generated by Drizzle Kit into `backend/drizzle/` (`drizzle.config.ts`).

### Simulation Engine

- Monotonic virtual clock (`src/simulation-engine/core/simulation-clock.ts`).
- Min-heap deterministic event queue (timestamp, then insertion sequence) (`src/simulation-engine/core/event-queue.ts`).
- Simulation runtime managing requests and per-component state (`src/simulation-engine/core/simulation-runtime.ts`).
- Engine orchestrator (`src/simulation-engine/core/simulation-engine.ts`).
- Graph traversal/topology (`src/simulation-engine/topology/architecture-topology.ts`).
- Default event processor with component runtime behaviour: health-failure and capacity checks, latency-based scheduling, linear routing (`src/simulation-engine/processor/event-processor.ts`).
- Component runtime state model (`src/simulation-engine/components/component-runtime-state.ts`).

### Tests

- Vitest unit suite: auth, project, architecture, middleware, lib, config, and simulation engine (clock, queue, topology, engine, event processor).
- Vitest integration suite: API (auth/project/architecture), repository, cascade deletion against a real Postgres service.

### CI/CD

- Backend workflow (`.github/workflows/backend-ci.yml`): lint, format check, typecheck, build, plus unit + integration tests with a `postgres` service container.
